# ASTRA: architecture

**ASTRA** works as a pipeline: **Ask** → **Fast path** → **Agent** → **Docs RAG** → **Confirm** → **Inference**. Ask: An ASTRA panel on every page of Cygnus. Operators ask about cameras, recordings, events, incidents and the estate, or ask to be taken to a page. Fast path: Common questions, such as counts, today's incidents or a camera's status, are recognised in code and answered from live data in about 0.1 s, without the model. Agent: Everything else goes to an agent loop on the Node server, where Qwen3-4B picks from dozens of tools. Each tool calls the server's own routes with the operator's token, so permissions and site scope always apply. Docs RAG: Feature questions are answered from the product docs: BM25 and bge-small search fused with reciprocal rank fusion, with chunks that name an exact identifier ranked first. Confirm: Changes such as PTZ moves, renames or tracking a number plate are proposed as a confirmation card and run only when the operator confirms. Admin-only changes are escalated to administrators. Inference: Qwen3-4B Q4_K_M on llama.cpp, on CPU, behind a token-protected service with Prometheus metrics. The warmed prompt is saved and restored, so a restart is ready in 6 s instead of 51 s.
