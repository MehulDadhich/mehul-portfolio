# Arc: architecture

**Arc** works as a pipeline: **Hybrid search** → **Prompt** → **Llama 3.2 3B** → **Actions** → **Memory** → **QLoRA fine-tune** → **Evaluation**. Hybrid search: The site's content is exported into a knowledge base. BM25 keyword search and bge-small dense embeddings are fused, with a boost for the project being asked about and a relevance floor that drops weak matches. Prompt: Instructions, the visitor's notes, the retrieved facts and the recent turns are packed into a 3,000-token budget. Llama 3.2 3B: Served by llama.cpp as a 4-bit GGUF and streamed token by token. The model sits behind one interface, so switching to a hosted model is a configuration change. Actions: Rules decide when a message asks for an action: scroll to a section, download the resume, open a repository. Arc offers it with Yes and No buttons and runs it only after the visitor agrees. Memory: Conversations and short notes about the visitor are stored in Firestore under an anonymous Firebase sign-in, so no visitor can read another's. QLoRA fine-tune: Qwen2.5-1.5B in 4-bit NF4 with rank-16 LoRA adapters on every projection (18.5M trainable parameters, 1.18%), trained on 745 grounded examples built from Arc's own retrieval in 46 minutes on an RTX 3050, then merged and quantized to GGUF. Evaluation: Base and fine-tuned models compared on 105 held-out questions, scored on the facts each answer must contain. A later Qwen3-4B fine-tune scored below its base model, so Arc now serves a stock model with stronger retrieval.
